01
PROJECT OVERVIEW

프로젝트 개요

TCAID : TCAD AI Manager는 기존 Synopsys Sentaurus Workbench를 유지하면서 연구자의 자연어 요청부터 코드 검토·승인, 실제 TCAD 실행, 결과 회수와 비교를 하나의 연구 흐름으로 연결하는 Human-in-the-loop 연구 자동화 시스템입니다.

연구의 핵심

AI는 연구 의도 정리와 코드 제안을 담당하고, 사용자는 변경 내용을 검토·승인하며, 실제 소자·공정 계산은 Sentaurus가 수행합니다. 자동화를 늘리는 것보다 연구자의 통제권과 원본 프로젝트 보호를 먼저 설계했습니다.

02
MOTIVATION & DESIGN GOAL

연구 배경과 문제 정의

기존 연구 과정의 병목

TCAD 연구에서는 Workbench 프로젝트 확인, CMD·TCL 수정, Windows–Linux 환경 이동, Sentaurus 실행, 결과 회수 및 조건별 비교가 반복됩니다. 일반 LLM을 사용해 코드 생성 시간을 줄여도 생성된 코드의 검토·반영과 원격 실행, 결과 정리를 사용자가 직접 연결해야 하는 부담이 남아 있습니다.

BEFORE · MANUAL CONNECTION연구자 중심 수작업

연구 의도 전달 → 코드 수령 → 프로젝트 직접 수정 → SSH 접속·실행 → 파일 회수 → 재분석

AFTER · TCAID WORKFLOW승인 중심 연구 관리

자연어 요청 → 조건 협의 → 프로젝트 기반 코드 제안 → 사용자 승인 → 격리 사본 실행 → 결과·지표 연결

개발 목표

기존 프로젝트의 파일·노드 관계를 읽기 전용으로 분석하고, 미확정 실험 조건은 질의응답으로 확정한 다음, 사용자 승인 이후에만 원본 밖의 실행 공간을 생성하도록 했습니다. 결과를 단순 다운로드 파일이 아닌 실행 조건과 추출 지표가 이어진 기록으로 다루는 것도 중요한 목표였습니다.

03
SYSTEM DESIGN

시스템 아키텍처

관리 환경은 Windows, 계산 환경은 Linux로 분리했습니다. TCAID는 SSH/SFTP로 Workbench 및 Sentaurus 계산환경과 연결되지만, 자체적으로 반도체 물리 계산을 대체하지 않습니다.

근거와 권한을 분리하는 설계

Read-only by default

원본 Workbench 프로젝트는 분석의 기준이지만 직접 수정하지 않습니다.

Explicit approval

AI의 제안과 실제 코드 적용 권한을 분리하고 사용자 승인으로 연결합니다.

Fail-closed

적용 여부가 불확실하거나 권한·무결성 검증에 실패하면 계속 실행하지 않습니다.

Provenance

연구 의도, 승인, 사본, 실행, 결과 파일, 지표의 연결 관계를 남깁니다.

04
HUMAN-IN-THE-LOOP

연구 자동화 Workflow

자연어 입력이 즉시 서버 명령이 되는 것이 아니라, 협의–검토–승인–실행의 별도 관문을 거칩니다.

01목표 입력연구자가 SProcess·SDevice 목표를 자연어로 요청
02조건 구조화확정·제안·미해결 조건을 구분하고 추가 질문
03프로젝트 확인기존 Workbench 상태를 읽기 전용으로 분석
04코드 제안예제 기반 코드 생성 및 변경 전후 diff 표시
05명시적 승인사용자가 변경 내용과 대상 검토 후 허용
06격리 실행원본 외부에 작업 사본을 만들고 Sentaurus 실행
07결과 회수SFTP, hash 및 manifest로 결과 확인
08지표·이력run별 결과·수치 비교와 다음 연구 판단 지원
05
APPLICATION INTERFACE

핵심 기능 구현

자연어로 시작하는 조건 협의

예를 들어 “게이트 길이 15 nm의 nMOS를 SProcess로 만들어줘”라는 요청에서 시작해 구조, 완료 기준, 필요한 파라미터 등을 확인합니다. 미확정 상태와 AI가 추천한 값을 사용자 입력과 구분한 후 의도를 확정합니다.

코드 변경 제안과 승인

생성된 코드의 적용 값, 참고 근거, 변경 대상과 diff를 제시하고, 연구자가 내용을 확인한 후에만 적용할 수 있습니다. 승인 기록의 범위가 변경되었거나 무효해진 경우 실행할 수 없도록 설계했습니다.

Windows–Linux 연동과 파일 신뢰성

실제 서버의 host key 확인, 비밀번호 미저장, 결과 전송 전후 파일 상태 확인 및 SHA-256 manifest를 적용했습니다. 원격 명령 응답이 끊긴 경우 결과를 임의로 성공 판정하지 않고 확인이 필요한 상태로 남깁니다.

06
TCAD EXPERIMENT

실제 SProcess·SDevice 시연

SProcess · 15 nm nMOS 구조 생성

실험 조건 협의 후 SProcess CMD를 생성하고 격리된 Workbench 사본에서 실행했습니다. SVisual로 생성된 2D 구조와 3D mesh를 확인했습니다. 이는 시뮬레이션 실행과 구조 생성의 확인이며, 생성된 소자 구조가 물리적으로 최적이라는 검증과는 구분됩니다.

SDevice · Drain bias 두 조건 비교

자연어로 서로 다른 drain 전압에서 전류 비교를 요청하고, VD = 0.5 V / 1.0 V 두 조건을 Workbench node로 구성했습니다. 각각 실행한 뒤 결과 파일을 회수하고 같은 정의의 ion_max 값을 추출해 정량 비교했습니다.

AI 해석 기능 범위

단일 run을 선택하여 해석을 요청하는 UI까지 구현했습니다. 두 개 이상의 run을 동시에 비교하여 물리적 원인을 자동 해석하는 기능은 해당 대회 시연의 검증 범위에 포함되지 않았습니다.

07
EVIDENCE & RESULTS

검증 결과와 성능

1-Cycle 작업시간 비교

경진대회에서 동일 목표의 1-Cycle 작업 흐름을 비교했습니다. 범용 LLM을 사용자가 직접 활용한 경우 약 67분, TCAID를 통한 경우 29분 13초가 소요되었습니다. 이 비교에서는 전체 작업시간이 56.4% 단축된 것으로 정리되었습니다.
